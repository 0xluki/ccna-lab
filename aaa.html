Step 12

AAA with RADIUS

Goal. Make R1 and R2 check remote logins against the RADIUS service on the server (172.16.1.10), with the local user database as a safety fallback. This lab uses authentication only: no authorization step.
Concept. AAA stands for Authentication, Authorization and Accounting; here we use only the first. Authentication answers “who are you?”. With aaa new-model the old line passwords are replaced by method lists, tried in order. RADIUS is a central login server: the router (the RADIUS client) forwards the username and password to it over UDP 1812, protected by a shared secret configured on both sides. In group radius local the router asks the server first and uses the local database only if the server does not answer (timeout). If the server answers “reject”, the login fails; there is no fallback. Since there is no authorization, a user who logs in lands in normal user mode and types enable (Cisco123) to go further.
Before you start. OSPF works and R1 can ping 172.16.1.10 (Step 10), ACLs are in place (Step 11) and SSH from PC4 works (Step 5). Keep a console session open while changing AAA so a mistake cannot lock you out.

Your tasks

  1. Server first. Click the Server → Services → AAA. Turn the service On. Add two clients with ServerType Radius and the secret LabKey123: R1 with Client IP 192.168.10.241 and R2 with Client IP 172.16.1.1. (A router sends RADIUS requests from the interface facing the server, so use those interface addresses, not the management address.)
  2. On the same page add a user in User Setup: username raduser, password Rad123. This account exists only on the server; admin exists only locally, which lets you tell the two apart in tests.
  3. On R1 and R2 point the router to the server: host 172.16.1.10 with key LabKey123.
  4. Enable aaa new-model.
  5. Create the default login method list: RADIUS.
  6. Apply the lists: VTY lines use default.
  7. Test RADIUS: from PC4 run ssh -l raduser 192.168.10.225 (R1) and 192.168.10.242 (R2). Password Rad123 must work; a wrong password must fail.
  8. Test the fallback: turn the server’s AAA service Off, wait for the timeout, then log in as admin / Admin123. It works only now because the server stopped answering. Turn AAA back On afterwards.

Hints

Hint 1

Server says “access rejected” for no reason? Check the client IP: it must match the interface the router uses to reach the server (R1 → its G0/1 address, R2 → its G0/1 address), and the secret must match exactly (case sensitive).

Hint 2

The router side is a single global command starting with radius-server host, followed by the server IP and key.

Hint 3

List syntax: aaa authentication login <list-name> <method1> <method2>. Methods are written group radius and local, in that order.

Hint 4

A list called default is applied to every line automatically; the CONSOLE list must be applied under line console 0 with login authentication CONSOLE.

Verify

Command / test Expected result
show running-config | include aaa|radius aaa new-model, both method lists and the radius-server host line
ssh -l raduser 192.168.10.225 (PC4) Password Rad123 accepted; prompt is R1> (user mode)
