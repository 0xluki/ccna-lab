Step 3

VLANs & Access Ports

Goal. Create the VLANs, place hosts in them, and give each switch a management address.
Concept. A VLAN is a separate broadcast domain, normally one per subnet. An access port belongs to one VLAN and talks untagged to an end device. VLANs exist per switch, so you create them on both. The management SVI (a virtual interface in VLAN 99) is the IP address you will later SSH to.
Before you start. Step 1 answers (mgmt subnet 192.168.10.224/28, gateway .225).

Your tasks

  1. On both switches create: VLAN 10 SALES, 20 HR, 30 IT, 99 MGMT, 999 BLACKHOLE (unused/native VLAN).
  2. On SW2 make Fa0/10 an access port in VLAN 10, Fa0/11 in VLAN 20 and Fa0/12 in VLAN 30 (PC1, PC2, PC3).
  3. On SW1 make Fa0/10 an access port in VLAN 99 (admin PC4).
  4. Create interface vlan 99 on each switch: SW1 = 192.168.10.226, SW2 = 192.168.10.227, mask 255.255.255.240, then no shutdown.
  5. Set each switch’s default gateway to 192.168.10.225 (future router address).
  6. On PC4 set a static IP 192.168.10.228, mask 255.255.255.240, gateway 192.168.10.225.
  7. PC1–PC3 stay unaddressed for now.

Hints

Hint 1

Naming a VLAN is a sub-command inside vlan <id>.

Hint 2

Access ports need switchport mode access first, then switchport access vlan <id>.

Hint 3

A switch’s gateway is set globally with ip default-gateway, not on the SVI.

Verify

show vlan briefFa0/10 listed under VLAN 99 on SW1; Fa0/10-12 under 10/20/30 on SW2
show ip interface briefVlan99 up/up with the right IP (up/up needs a connected port in VLAN 99 or a trunk)
