Step 14

Troubleshooting Scenarios

Goal. Practise real-world troubleshooting: inject a fault, observe the symptom, find the root cause, then fix it.
How to use this page. Save a working copy of your .pkt first. Do one scenario at a time: apply the “break it” change, use only the listed show commands to diagnose, then open the answer to check yourself. Undo the fault before the next scenario.

Scenario 1 – PC1 can’t reach PC2 (inter-VLAN)

Break it: On R1: interface g0/0.20 → encapsulation dot1q 200

Symptom: PC2 loses its gateway; PC1 → PC2 fails.

Investigate with: show ip interface brief, show running-config interface g0/0.20, show vlan brief

Show cause & fix

Subinterface encapsulation (200) doesn’t match VLAN 20. Fix: encapsulation dot1q 20.

Scenario 2 – SSH refused

Break it: On R1: line vty 0 15 → transport input telnet

Symptom: PC4’s SSH attempt is refused.

Investigate with: show running-config | section line vty, show ip ssh

Show cause & fix

VTY allows only Telnet. Fix: transport input ssh. Also check domain name and keys exist.

Scenario 3 – Trunk down / native mismatch

Break it: On SW2: interface port-channel 1 → switchport trunk allowed vlan 10,20,30

Symptom: VLAN 99 traffic dies; PC4 can’t ping SW2 or R1.

Investigate with: show interfaces trunk on both switches, compare “allowed” lists

Show cause & fix

VLAN 99 missing from the allowed list on one side. Fix: add it back (switchport trunk allowed vlan add 99). Native VLAN mismatches show as CDP warnings.

Scenario 4 – OSPF neighbour stuck

Break it: On R2: interface g0/0 → ip ospf hello-interval 20

Symptom: R1 loses the server route; neighbour flaps/EXSTART/INIT.

Investigate with: show ip ospf neighbor, show ip ospf interface g0/0 on both

Show cause & fix

Hello/dead timers mismatch. Fix: no ip ospf hello-interval. Also check area, subnet mask and passive-interface on the link.

Scenario 5 – EtherChannel suspended

Break it: On SW2: interface range fa0/1-2 → channel-group 1 mode passive and on SW1 change to passive too

Symptom: Po1 shows (SD) or ports (I); STP blocks a link again.

Investigate with: show etherchannel summary, show etherchannel port-channel

Show cause & fix

Passive/passive never negotiates. Fix: set at least one side to active. Also check identical trunk settings.

Scenario 6 – PCs get 169.254.x.x (no DHCP)

Break it: On R1: no ip dhcp pool HR, recreate with network 192.168.10.128 255.255.255.0

Symptom: HR clients get no lease or the wrong gateway/mask.

Investigate with: show ip dhcp pool, show ip dhcp binding, check the PC’s VLAN

Show cause & fix

Pool mask/network doesn’t match the VLAN 20 subnet (/26). Fix the pool network and mask; also confirm excluded ranges and the access VLAN.

Scenario 7 – Everything to the server is blocked

Break it: On R1: interface g0/1 → ip access-group SERVER-FILTER in

Symptom: Server replies are dropped; even Sales can’t reach it.

Investigate with: show access-lists (which line matches), show ip interface g0/1 (direction)

Show cause & fix

ACL applied in the wrong direction (replies are filtered). Fix: no ip access-group SERVER-FILTER in then apply out.
