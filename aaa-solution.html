Solution

AAA with RADIUS – full solution

Try the hints first. Configure the server before the routers, otherwise the first RADIUS login attempt is rejected.

1. Server (Services → AAA)

Services > AAA
  Service: On
  Radius clients (Network Configuration):
    Client Name: R1   Client IP: 192.168.10.241   Secret: LabKey123   ServerType: Radius   [Add]
    Client Name: R2   Client IP: 172.16.1.1       Secret: LabKey123   ServerType: Radius   [Add]
  User Setup:
    Username: raduser   Password: Rad123   [Add]

R1 sends requests from 192.168.10.241 (its G0/1, the interface toward the server); R2 sends from 172.16.1.1 (its G0/1, directly connected to the server).

2. R1 and R2 (same commands on both)

radius-server host 172.16.1.10 key LabKey123
aaa new-model
aaa authentication login default group radius local
line vty 0 15
 login authentication default
end
copy running-config startup-config

group radius local means: ask the RADIUS server; use the local user only if the server does not respond.

3. Test

! From PC4 command prompt
ssh -l raduser 192.168.10.225     (password Rad123, lands in R1>)
ssh -l raduser 192.168.10.242     (R2)
! On the router, if you want to watch it
debug aaa authentication
undebug all

Fallback test: turn the server’s AAA service Off, wait for the timeout, then ssh -l admin 192.168.10.225 with Admin123 works. Turn it back On afterwards.

Why the ACL doesn’t block this

The SERVER-FILTER ACL on R1 G0/1 is applied out and only filters transit traffic; packets created by R1 itself (the RADIUS request) are not filtered by an outbound ACL, and the server’s replies come in on G0/1 where no ACL is applied.
